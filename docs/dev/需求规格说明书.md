# SqlFM 需求规格说明书

> 版本：v1.0 ｜ 日期：2026-07-17 ｜ 状态：基线 ｜ 适用范围：SqlFM（SSMS 22.6 SQL 格式化扩展）

## 1. 引言

### 1.1 目的

本文档定义 SqlFM 的功能性与非功能性需求，作为设计、开发、测试与验收的统一依据。SqlFM 是一款深度集成于 SQL Server Management Studio（SSMS）22.6 的 T-SQL 格式化扩展，同时提供独立的命令行工具（CLI）用于批量处理与 CI/CD 集成。

### 1.2 范围

覆盖范围包括：

- SSMS 编辑器内的 SQL 格式化、大小写转换、SQL 重构、豁免保护；
- 可视化配置窗口与样式管理（预设、自定义、导入导出）；
- 命令行批量格式化与检查模式；
- 新增子系统：Lint 规则引擎、方言体系、补全引擎（框架已落地，部分能力待接入）。

不覆盖范围：数据库元数据采集（SELECT * 展开依赖外部连接）、SSMS 安装包本身的缺陷修复。

### 1.3 术语

| 术语 | 说明 |
|------|------|
| T-SQL | Transact-SQL，SQL Server 的过程化扩展 |
| VSIX | Visual Studio 扩展安装包格式 |
| ScriptDom | Microsoft.SqlServer.TransactSql.ScriptDom，T-SQL 解析器/AST 库 |
| PoorMans | Poor Man's T-SQL Formatter，核心格式化引擎 |
| 豁免区域 | 被标记从而跳过格式化的代码段 |
| .sqlstyle | SqlFM 样式配置文件（XML 序列化） |

## 2. 总体描述

### 2.1 产品前景

SqlFM 解决的核心痛点：DBA 与开发人员在 SSMS 中手写或粘贴的 SQL 排版混乱、风格不统一，缺乏内置于 IDE 的一键规范化工具。SqlFM 将格式化能力直接嵌入编辑器，并延伸到命令行与持续集成环节。

### 2.2 用户特征

| 角色 | 特征 | 关键诉求 |
|------|------|----------|
| DBA | 高频审阅/编写存储过程 | 一键规范化、关键字统一大写、保护手写排版 |
| 后端开发 | 编写业务 SQL | 实时预览、团队共享样式 |
| 平台工程 | 维护 SQL 仓库 | CLI 检查模式、CI 门禁、批量格式化 |

### 2.3 运行环境

| 组件 | 要求 |
|------|------|
| SSMS | 22.6.0 (x64) |
| 操作系统 | Windows 10 / 11 (x64) |
| 运行时 | .NET Framework 4.8（SSMS 22 自带） |
| 目标框架 | net48（VSIX 与 Core 库、CLI 一致） |

### 2.4 约束与依赖

- 依赖 PoorMansTSQLFormatter 1.4.3.1、ScriptDom 180.18.1、System.Data.SqlClient 4.9.1；
- VSIX 构建需 Microsoft.VisualStudio.SDK 17.6 + VSSDK.BuildTools 18.x，并通过后处理清除 .NET 8 DLL；
- 部分高级格式受 PoorMans 引擎限制（详见第 4 章已知限制）。

## 4. 非功能性需求

| 类别 | 需求 | 目标 |
|------|------|------|
| 性能 | 单文件格式化延迟 | 常规脚本 < 200ms（见性能测试） |
| 兼容性 | SSMS 22.6 x64 | 仅在该版本验证 |
| 可用性 | 零配置可用 | 默认预设即满足多数场景 |
| 可维护性 | 注释覆盖率 | 全量 .cs 100% XML 注释 |
| 容错 | 格式化失败 | 返回原文 + 错误信息，不破坏编辑器 |
| 安全 | 外部操作 | 不执行任意 SQL、不发起网络请求、不泄露代码 |
| 可移植性 | CLI 跨环境 | .NET Framework 4.8 运行时可执行 |

## 5. 数据需求

### 5.1 样式配置模型

`SqlFormatStyle` 聚合 8 个分组设置（Global/Dml/Cte/Case/Flow/Ddl/Expression/Tsql）+ 忽略规则，支持 XML 序列化，深拷贝通过序列化实现。

### 5.2 配置持久化

- VSIX 默认样式存于 `StyleManager`（AppSettings.DefaultStyleName）；
- 自定义样式以 `.sqlstyle` 文件在团队间共享。

---

## 6. 验收标准

1. FR-01~FR-07、FR-21~FR-25、FR-26、FR-31 必须为 P0 全部通过；
2. `dotnet test` 全量通过，无新增失败用例；
3. 默认预设下格式化结果幂等（二次格式化输出不变）；
4. 已知 PoorMans 限制项（第 4 章）需在用户文档中明确标注，不作为验收阻塞项。

## 7. 已知限制（需求层面）

| 限制 | 影响 | 处置 |
|------|------|------|
| PoorMans 解析器对 ALTER PROCEDURE 参数列表解析失败 | 行尾注释位置错乱 | 待决策：规避（NOFORMAT）或 ScriptDom 重写参数列表格式化 |
| 10 项高级对齐/缩进配置 PoorMans 不生效 | 部分配置项无效果 | 后续后处理实现或接受限制 |
| SELECT * 展开需元数据 | 离线不可用 | 需 SSMS DTE 或映射字典 |
