# SqlFM 软件设计说明书

> 版本：v1.0 ｜ 日期：2026-07-17 ｜ 状态：基线 ｜ 适用范围：SqlFM 解决方案（5 项目）

---

## 1. 引言

### 1.1 目的

说明 SqlFM 的体系结构、模块划分、核心流程、关键类设计与数据模型，为开发、评审与维护提供架构依据。

### 1.2 设计原则

- **关注点分离**：格式化内核（SqlFM.Core）不依赖 Visual Studio，可独立测试与 CLI 复用；
- **管道编排**：单一 `FormatterPipeline` 串联预处理、主引擎、后处理，职责清晰；
- **容错优先**：所有重构/后处理经 `SafeRefactor` 包裹，异常时回退原文，保证编辑器不崩溃；
- **双引擎互补**：PoorMans 负责主流格式化，ScriptDom 负责 AST 级精确操作（大小写、方括号、架构前缀、校验）。

## 2. 体系结构设计

### 2.1 解决方案结构

```
SqlFM.sln
├── src/
│   ├── SqlFM.Core/      （net48，无 VS 依赖：格式化内核）
│   ├── SqlFM/           （net48，VSIX 扩展主项目）
│   └── SqlFM.Cli/       （net48，命令行工具）
└── tests/
    ├── SqlFM.Tests/         （端到端格式化测试）
    └── SqlFM.Core.Tests/    （内核功能/性能测试）
```

### 2.2 分层与依赖

```
[SSMS 宿主] ──> SqlFM(VSIX) ──> SqlFM.Core <── SqlFM.Cli
                     │                │
                 DTE / VSCT       PoorMans + ScriptDom
```

- `SqlFM` 引用 `SqlFM.Core`；
- `SqlFM.Cli` 引用 `SqlFM.Core`；
- `SqlFM.Core` 不反向依赖 VS 或 CLI，保证可测试性。

## 3. 核心流程设计：格式化管道

`FormatterPipeline.Format(sql)` 执行 6 步流水线：

| 步骤 | 名称 | 组件 | 职责 |
|------|------|------|------|
| 1 | 预处理 | ExemptionProcessor | 识别并抽取豁免区域，以占位符替换 |
| 2 | 预重构 | JoinConverter | 隐式 JOIN 转显式 INNER JOIN（结构级变换） |
| 3 | 主格式化 | PoorMansEngine | tokenizer → parser → formatter，输出标准排版 |
| 4 | 后处理 | 多个后处理器 | 清理/大小写/方括号/架构前缀/T-SQL/对齐 |
| 5 | 恢复豁免 | ExemptionProcessor | 占位符还原为原代码 |
| 6 | 最终清理 | FormatterPipeline | 确保文件末尾单个换行 |

**后处理子阶段（Step 4）展开：**

1. 基础清理（行尾空格、连续空格、多余空行）
2. 大小写转换（CasePostProcessor：函数名/数据类型）
3. 重构操作（BracketNormalizer、SchemaPrefix、UppercaseGlobalVariables）
4. T-SQL 规则 + 纵向对齐（TsqlNameFormatter、AlignmentPostProcessor）

所有子阶段通过 `SafeRefactor` 包裹：失败返回原文，不中断管道。

## 4. 模块设计

### 4.1 SqlFM.Core（内核）

| 子模块 | 关键类 | 职责 |
|--------|--------|------|
| Engine | FormatterPipeline / PoorMansEngine / ScriptDomEngine / CasePostProcessor / AlignmentPostProcessor / TsqlNameFormatter | 格式化编排与执行 |
| Configuration | SqlFormatStyle + 8 个 Settings + Enums + StyleSerializer | 样式定义与序列化 |
| Exemption | ExemptionProcessor / FormatOffOnParser / NoFormatLineParser / RegexIgnoreRule | 豁免区域管理 |
| Refactoring | JoinConverter / BracketNormalizer / SchemaPrefix / StarExpander | SQL 结构变换 |
| Lint | SqlRuleEngine / SqlRule / LintResult / LintFix / Rules/* | 规则引擎（25 条规则/6 组） |
| Dialects | SqlDialect / AnsiDialect / TsqlDialect / DialectRegistry + KeywordSets | 方言与关键字集 |
| Completion | SqlCompletionEngine / CompletionProviders / Snippets | 补全引擎框架 |
| PresetStyles | PresetStyleFactory | 5 套内置预设 |
| Batch | FileBatchProcessor / DbMetadataBatch | 文件/数据库批量格式化 |

### 4.2 SqlFM（VSIX 扩展）

| 模块 | 关键类 | 职责 |
|------|--------|------|
| Package | SqlFMPackage | 命令注册、右键菜单注入（DTE）、保存自动格式化（RDT 事件） |
| Commands | FormatSelected/FormatAll/FormatOptions/CaseUpper/CaseLower/InsertExemption | 6 组命令 |
| Editor | EditorHelper | 读取/替换编辑器文本 |
| Services | FormatService / StyleManager | 格式化入口与样式管理 |
| Options | GeneralOptionsPage / SettingsWindow.xaml(.cs) / SettingsViewModel / OptionsExporter | 配置页与 WPF 窗口 |

### 4.3 SqlFM.Cli

- `Program.Main`：参数解析 → 样式加载 → 单文件/目录处理 → 退出码；
- `CliOptions`：命令行选项与编码解析；
- 退出码语义：0=无需修改，1=已格式化/需格式化，2=部分失败，3=参数错误，4=致命错误。

## 5. 关键类设计

### 5.1 FormatterPipeline

- 角色：Core 对外统一入口（Facade + Orchestrator）；
- 字段：PoorMansEngine、ScriptDomEngine、ExemptionProcessor、BracketNormalizer、SchemaPrefix、JoinConverter、CasePostProcessor、AlignmentPostProcessor、TsqlNameFormatter；
- 关键方法：`LoadStyle(style)`、`Format(sql) → FormatResult`、`ValidateSyntax(sql, out errors)`；
- 容错：try/catch 返回 `FormatResult{Success=false, ErrorMessage}`。

### 5.2 PoorMansEngine / ScriptDomEngine

- PoorMansEngine：封装 Poor Man's 的 `TSqlStandardFormatter`，13 参数构造函数映射配置；
- ScriptDomEngine：基于 `TSql160Parser` 的 AST 校验、对象名提取、语句类型识别。

### 5.3 ExemptionProcessor

- 合并 3 种豁免源（FORMAT OFF/ON、NOFORMAT、正则）为统一占位符序列；
- PreProcess 抽取 → PostProcess 还原。

### 5.4 SqlRuleEngine（Lint）

- 注册表：`_codeMap` / `_nameMap` / `_groupMap` 三索引；
- 支持 `FilterRules(enableOnly, disable)` 与 `GetRulesForDialect(dialect)`；
- 规则基类 `SqlRule`，结果 `LintResult`，修复 `LintFix`。

### 5.5 Dialect 体系

- `SqlDialect` 抽象基类定义关键字集与规则适配；
- `AnsiDialect` / `TsqlDialect` 继承；
- `DialectRegistry` 注册 Ansi/Tsql/MySql/PostgreSql/Oracle/BigQuery。

## 6. 数据设计

### 6.1 配置模型（SqlFormatStyle）

```
SqlFormatStyle
├── GlobalSettings      (缩进/行宽/大小写/空白/分号/引号/方括号)
├── DmlSettings         (逗号/AS/JOIN/WHERE/GROUP BY/INSERT/UPDATE/MERGE)
├── CteSettings         (CTE 换行/缩进/空行/递归)
├── CaseSettings        (WHEN/THEN/ELSE/END)
├── FlowSettings        (IF/BEGIN/TRY/CATCH/DECLARE/EXEC)
├── DdlSettings         (CREATE TABLE/PROC/FUNCTION/TRIGGER)
├── ExpressionSettings  (运算符/子查询/注释)
├── TsqlSettings        (dbo 前缀/临时表/表变量/全局变量)
└── IgnoreConfig        (RegexIgnoreRules: List<string>)
```

### 6.2 .sqlstyle 文件格式

XML 根 `SqlFormatStyle`，各分组为子元素，可经 `StyleSerializer` 序列化/反序列化；`IsSystemPreset` 标记内置预设（不可删除）。

## 7. 接口设计

### 7.1 内部接口

- `IFormatterEngine`：`Format(sql)` / `Validate(sql, out errors)` / `Configure(style)`。

### 7.2 外部集成接口

- **SSMS DTE**：通过 `EnvDTE80.DTE2` 注入右键菜单、读取/替换编辑器文本；
- **VSCT 命令表**：`SqlFMCommandTable.vsct` 定义菜单、工具栏、上下文菜单与 6 组快捷键；
- **RDT 事件**：`IVsRunningDocTableEvents3.OnAfterSave` 实现保存自动格式化。

---

## 8. 容错与安全设计

- **容错**：`SafeRefactor` 统一包裹后处理；`Format` 整体 try/catch；预重构 JOIN 转换失败静默跳过；
- **安全**：不执行用户 SQL、不发起网络请求、不读取/外传代码内容；CLI 仅读写本地文件；
- **降级**：ScriptDom 解析失败时相关后处理返回原文，主格式化结果仍可用。

## 9. 已知限制与设计权衡

| 限制 | 根因 | 设计权衡 |
|------|------|----------|
| ALTER PROCEDURE 参数列表注释错乱 | PoorMans 解析器不支持 | 暂用 NOFORMAT 规避；可选 ScriptDom 重写 |
| 10 项高级对齐配置无效 | PoorMans 缩进层级固定 | 后处理实现成本高，部分接受限制 |
| SELECT * 离线不可展开 | 缺元数据 | 保留 StarExpander，接入需 DTE/映射字典 |
| VSIX 含 .NET 8 DLL 风险 | VSSDK.BuildTools 18.x 工具链 | 后处理 Target 清除 .NET 8 DLL |
