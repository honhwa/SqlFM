# SqlFM 测试方案与测试报告

> 版本：v1.0 ｜ 日期：2026-07-17 ｜ 状态：基线 ｜ 测试框架：xUnit.net

---

## 1. 引言

### 1.1 目的

定义 SqlFM 的测试策略、范围与用例，并记录当前测试执行结果，作为质量评估与后续优化依据。

### 1.2 测试对象

- `SqlFM.Core` 格式化内核（管道、引擎、后处理、豁免、重构、Lint）；
- `SqlFM` VSIX 命令与配置窗口（端到端）；
- `SqlFM.Cli` 命令行工具。

---

## 2. 测试策略

| 测试类型 | 范围 | 框架/工具 | 目标 |
|----------|------|-----------|------|
| 单元测试 | 各引擎/后处理器独立逻辑 | xUnit | 单点正确性 |
| 端到端测试 | FormatterPipeline.Format 全链路 | xUnit | 输入→输出符合预期 |
| 性能测试 | 单文件格式化延迟 | xUnit（Stopwatch） | 常规脚本 < 200ms |
| 幂等性测试 | 二次格式化输出不变 | xUnit | 稳定性 |

**分层原则**：`SqlFM.Core` 不依赖 VS，可在无 SSMS 环境运行全部内核测试；`SqlFM.Tests` 侧重端到端行为。

## 5. 代表性测试用例

## 7. 缺陷与限制

### 7.1 PoorMans 引擎限制（10 项，待后处理实现）

| 配置项 | 现象 |
|--------|------|
| Dml.OnConditionIndent | 缩进层级固定，配置不生效 |
| Dml.LogicOperatorBefore | AND/OR 无法前置行首 |
| Dml.OrderBySortAlign | ASC/DESC 不对齐 |
| Case.ThenValueAlign | THEN 值不对齐 |
| Ddl.ConstraintAlign | 约束定义不对齐 |
| Flow.IfElseBlankSplit | IF/ELSE 间不插入空行 |
| Ddl.TriggerInsertedIndent | inserted/deleted 缩进不调整 |
| Cte.WithSingleLine | 仅 SingleLineCompact 预设生效 |
| Cte.RecursiveCteUnionIndent | PoorMans 不单独处理 |
| Case.ShortCaseSingleLine | 仅 SingleLineCompact 预设生效 |

### 7.2 需外部依赖（2 项）

- SELECT * 自动展开（需 SSMS DTE 元数据）；
- SELECT * 展开 CLI（需用户提供映射字典）。

### 7.3 已知待决策缺陷

- **ALTER PROCEDURE 参数列表行尾注释位置错乱**：PoorMans 解析器对参数列表解析失败，输出 `--WARNING! ERRORS ENCOUNTERED DURING SQL PARSING!`，参数被压缩一行，注释位置错乱。处置方案待定：A) 规避（NOFORMAT 标记）+ 文档说明；B) 用 ScriptDom 重写参数列表格式化。

### 7.4 测试覆盖盲区

- Lint 规则引擎（25 条规则）无专项单元测试；
- 方言体系、补全引擎处于框架阶段，缺集成测试；
- CLI 退出码矩阵（0-4）无自动化校验用例。

---

## 8. 测试结论与建议

**结论**：核心格式化链路质量稳定，活跃用例 100% 通过，注释与编译质量达标，满足 P0 需求验收基线。

**建议**：

1. 为 Lint/SqlRuleEngine 补专项测试（覆盖 6 组 25 条规则）；
2. 为 CLI 退出码矩阵补充参数化测试；
3. 将 PoorMans 限制项逐条登记为 GitHub Issue，明确处理优先级；
4. 针对 ALTER PROCEDURE 注释缺陷尽快决策 A/B 方案并补充回归用例；
5. 在 CI 中加入 `dotnet test` 门禁与性能基准阈值。
